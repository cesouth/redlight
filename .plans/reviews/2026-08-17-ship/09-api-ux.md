## Summary

The public surface is 33 symbols and it is in better shape than a package this
young usually is: keyword-only arguments are used consistently for everything
optional, in-place mutation is documented at every call site that does it, no
dead private helpers, no rename residue, and the three optional dependencies are
genuinely deferred. The one real defect is a first-run stumble —
`examples/README.md` promises that every script fails with an actionable message
if you skip the setup step, and the single script it tells you to run first is
the one that does not. Everything else is naming coherence, which is real but
belongs to 0.7.

### F-9.1 — The first example a new user is told to run is the one that does not check for the sample data
- **Severity:** S2
- **Location:** `examples/01_basics/load_match_derive.py`; claim at
  `examples/README.md:15-16`
- **Claim:** `examples/sample_data/` is gitignored and generated by
  `00_setup/generate_sample_data.py`, so a fresh clone does not have it. The
  README states: *"The generator writes `examples/sample_data/` (git-ignored).
  Every other script fails with an actionable message if you skip it."* That is
  true of seven of the eight — but not of `01_basics/load_match_derive.py`, the
  script the README's "Start here" block names.
- **Evidence:** with `examples/sample_data/` moved aside:
  ```
  net = rl.Network.from_geojson(os.path.join(DATA, "network.geojson"))
    File ".../redlight/network.py", line 337, in from_geojson
      with open(path, encoding="utf-8") as fh:
  FileNotFoundError: [Errno 2] No such file or directory:
    '.../examples/sample_data/network.geojson'
  ```
  The guard exists and is exactly right — `examples/_common.py:25`:
  ```python
  def require_sample_data() -> None:
      """Fail with an actionable message rather than a FileNotFoundError."""
  ```
  and its adoption:
  ```
  00_setup/generate_sample_data.py            -- rolls its own paths   (correct: it CREATES the data)
  01_basics/load_match_derive.py              -- rolls its own paths   <-- the gap
  02_speed_analysis/clean_and_aggregate.py    uses _common
  02_speed_analysis/peak_and_daytype.py       uses _common
  03_mode_screening/screen_pedestrians.py     uses _common
  04_congestion/congestion_vs_limits.py       uses _common
  05_network/routing.py                       uses _common
  05_network/structure_and_chokepoints.py     uses _common
  06_mapping/export_map.py                    uses _common
  ```
- **Expected vs actual:** The README makes a promise the package almost keeps.
  The one place it breaks is the highest-traffic path in the whole project —
  a new user's second command. `01_basics` deliberately avoids `_common` so the
  core pipeline reads end-to-end without indirection, which is a good reason to
  keep its explicit paths; it is not a reason to skip the check.
- **Suggested fix:** Call `require_sample_data()` at the top of
  `01_basics/load_match_derive.py`, or inline the same three-line check so the
  script stays self-contained. Either keeps the README's claim true.
- **Verdict:** ACCEPT
- **Outcome:** fixed (8fb2870) -- guard inlined, plus tests/test_examples.py holding the
  README's promise for all eight examples

### F-9.2 — `--out foo.png --format png` silently writes a directory named `foo/`
- **Severity:** S5
- **Location:** `scripts/customer_report.py` (`--out` handling)
- **Claim:** With `--format png` the output is a directory of nine PNGs plus
  `captions.md`. Passing `--out rep.png` produces `rep/`, not `rep.png` — the
  extension is stripped and the path reinterpreted, with no warning.
- **Evidence:**
  ```
  $ ... --out .../rep.png --format png
  Wrote .../rep/ (9 PNGs + captions.md)  (9 figures, format=png)
  $ ls .../rep.png
  ls: ...: No such file or directory
  ```
  The help text does say `--out OUT  output file (or directory, for --format
  png)`, so the behaviour is documented — but the reinterpretation of a path the
  user explicitly named is not.
- **Expected vs actual:** Either honour the name given, or say what happened:
  *"--format png writes a directory; using rep/ rather than rep.png"*. Silently
  writing somewhere other than the path the user typed is the part worth fixing,
  not the directory-vs-file design.
- **Suggested fix:** One line printing the resolved destination when it differs
  from `--out`. Overwrite behaviour itself is fine — a rerun replaces its own
  figures and leaves unrelated files in the directory alone (verified).
- **Verdict:** ACCEPT
- **Outcome:** fixed (666b53a)

### F-9.3 — Three parameter names for one concept: `unit`, `output_unit`, `speed_unit`
- **Severity:** S5
- **Location:** across `redlight.__all__`
- **Claim:** The same idea — "which speed unit is this value in" — is spelled
  three ways, and the split does not follow a rule a user could infer.
- **Evidence:**
  ```
  unit         (7)  classify_movers, filter_by_speed, filter_trajectory_speed,
                    from_mps, mover_features, suggest_mode_threshold, to_mps
  speed_unit   (4)  load_points, plot_speed_map, save_points, to_geojson
  output_unit  (3)  aggregate_speeds, congestion_report, day_type_report
  ```
  A plausible rule — `unit` for interpreting inputs, `output_unit` for return
  values, `speed_unit` for file and render I/O — does not hold: `to_geojson`
  and `plot_speed_map` take `speed_unit` for what is unambiguously an *output*
  unit, while `aggregate_speeds` calls the same thing `output_unit`.
- **Expected vs actual:** A user who has learned `aggregate_speeds(output_unit=
  "kph")` will guess `to_geojson(output_unit="kph")` and get a `TypeError`.
  Note this is naming only — Task 3 verified the conversion constants are exact
  and that m/s is genuinely the internal representation throughout.
- **Suggested fix:** Signature change, so **out of scope to fix**; see the
  deferred section below.
- **Verdict:** DEFER -- signature change; recorded under "Deferred to a future major version".
- **Outcome:** deferred to a future major version; see the section below

### F-9.4 — Four suffixes for "returns a dict of summary numbers"
- **Severity:** S5
- **Location:** across `redlight.__all__`
- **Claim:** `_report`, `_stats`, `_analysis` and bare nouns all name functions
  that return a summary `dict`, with no distinction between them.
- **Evidence:**
  ```
  report    congestion_report, connectivity_report, day_type_report
  stats     network_stats
  analysis  peak_analysis
  hours     classify_hours          <- also returns a dict
  ```
  Ten of the eighteen public functions return `dict`; six return
  `pd.DataFrame`; the split is not signalled by the name. `classify_hours`
  returns a dict while its near-namesake `classify_movers` returns a DataFrame.
- **Expected vs actual:** The convention question the plan asked — "are
  `_report` and `_stats` used to mean consistent things?" — answers *no*: they
  are interchangeable. `classify_hours` vs `classify_movers` returning different
  container types under the same verb is the sharpest instance.
- **Suggested fix:** Naming change, **out of scope**; see below. In the interim,
  `docs/api.md` could group the public surface by return type, which is free and
  helps more than a rename would in the near term.
- **Verdict:** DEFER -- naming change; recorded under "Deferred to a future major version".
- **Outcome:** deferred to a future major version; see the section below

## Deferred to a future major version

These require changing a name or signature in `redlight.__all__`. No severity
assigned, per the pass brief.

**1. Unify the unit parameter on `unit=`.** One spelling everywhere. Migration:
accept the new name alongside the old for one minor version, warn on the old,
remove in the next major. `to_mps`/`from_mps` already use `unit=`, so it is the
established spelling and the smallest disruption — it renames 7 uses to 0 and
leaves 7 already correct.

**2. Make the return-type convention legible.** The cheapest coherent rule:
`_report` returns a dict intended for humans (nested, with prose keys),
everything else returns a DataFrame. Under that rule `network_stats` →
`network_report`, `peak_analysis` → `peak_report`, and `classify_hours` — which
returns a dict of two hour lists — is the odd one out either way. Worth deciding
deliberately in 0.7 rather than drifting further.

**3. `Network.__init__` takes nine positional arguments** (`graph`,
`crs_metric`, `edge_index`, `edge_geoms_proj`, `edge_ids`, `transformer_fwd`,
`transformer_inv`, `edge_lengths`, `reverse_of`). It is only ever called from
the `from_*` classmethods, and nothing in the docs suggests constructing one
directly — but it is public, so a user *can*, and the signature offers no help
if they try. Either make it keyword-only, or document it as internal and give
the classmethods sole responsibility.

## Unverified suspicions

   filesystem cache; a first import on a cold cache will be worse, and the
   notebook experience the plan was worried about depends on that number, not
   this one. Re-measure with the cache dropped if it ever matters.

   `examples/**`, and the nine `.py` scripts were all run, but the notebooks
   directory was not executed — notebooks need a kernel and their own runner,

   they are as capable of drifting as the prose Task 2 audited, and nothing
   currently runs them.

   but not run end-to-end** against sample data, unlike `customer_report.py`.
   Its output-file arguments (`--out-points`, `--out-movers`) were therefore not
